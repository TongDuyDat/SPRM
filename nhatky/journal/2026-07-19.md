## 2. Phân tích chậm train + VRAM thấp (root cause model pipeline)

### 2.1. Quan sát

| Metric | Giá trị | Ý nghĩa |
| --- | --- | --- |
| s/batch | ~6.5 | Không khớp ResNet-101 batch 24 trên T4 |
| GPU RAM | ~1/15 GB | Không full-train activation lớn |
| Trainable | ~4.2M / 112M | Vision + CLIP **freeze** (đúng config) |

### 2.2. Luồng 1 batch (trước khi fix cache)

```text
DataLoader 24 ảnh
    → ResNet-101 multilevel (freeze)     ~ nhanh tương đối
    → PSC: encode class_desc 150 seen
         itemwise: ~4 CLIP encode/class
         × 150 class ≈ 600 encode_text/batch  ← BOTTLENECK
    → Ws + IPR + matching (trainable nhỏ)
```

**Số liệu semantic CUB after-LLM** (`class_semantics.json`):

- Mỗi class: name 1 + attr 10 + hier 10 + desc 10 ≈ **31 text items**
- Itemwise gộp theo field → **~4 lần `encode_text` / class**
- Seen = 150 → **~600 lần CLIP text forward mỗi batch**, gọi **tuần tự** trong Python

Code liên quan:

- `trainer/trainer.py`: mỗi step `_prepare_semantic_input(seen_classes)` + `model(seen_attr, features)`
- `model/sematics/constructor.py`:
  - `forward`: loop từng class
  - `_encode_record_itemwise` khi `itemwise_pool: true`

### 2.3. Kết luận phân tích

| Câu hỏi | Trả lời |
| --- | --- |
| Sao không full VRAM? | Backbone freeze + mỗi lần CLIP text batch nhỏ, peak activation thấp |
| Sao batch 24 mà ~6 s? | ~600 CLIP text encode/batch, không phải ResNet “nặng” |
| Chỉ tăng batch / workers? | **Không** đủ để xóa bottleneck text |

## 3. Sửa đổi model / train — Hướng A: cache semantic khi freeze

### 3.1. Ý tưởng thiết kế

- CLIP text **freeze** → embedding `phi_t` **không đổi theo batch** (chỉ phụ thuộc class text).
- Encode **một lần** toàn bộ class lúc init Trainer (và eval standalone).
- Mỗi batch: truyền **tensor `phi_t` đã cache** vào PSC → bỏ CLIP; **`Ws` vẫn chạy** (trainable).

### 3.2. `model/sematics/constructor.py` (`PriSematicConstructor`)

| Thay đổi | Chi tiết |
| --- | --- |
| `_encode_texts` | Nếu `freeze_encoder`: bọc `torch.no_grad()` |
| `encode_class_phi(records)` | **Mới** — encode list `t_c` dict → tensor `(C, D)` phi_t (không qua `Ws`) |

`forward` vốn đã hỗ trợ value là **tensor** (pass-through) → cache inject được mà không đổi `HSPRN.forward` API.

### 3.3. `trainer/trainer.py`

| Thay đổi | Chi tiết |
| --- | --- |
| `self._phi_cache` | `(C, D)` trên `device`, hoặc `None` |
| `_semantic_encoder_is_frozen()` | Đọc `cfg.model.semantic.freeze` / `psc.freeze_encoder` |
| `_maybe_build_frozen_phi_cache()` | Gọi sau logger init; log thời gian + shape |
| `_prepare_semantic_input` | Ưu tiên trả dict tensor từ cache |

**Hành vi:**

- `semantic.freeze: true` + `class_desc` → **bật cache** (Plan 3 config hiện tại).
- `freeze: false` → không cache, encode mỗi batch như cũ (giữ đúng khi fine-tune text).

**Log kỳ vọng:**

```text
Caching frozen semantic phi_t for 200 classes (itemwise=True) …
Cached phi_t shape=(200, 512) device=cuda:0 in Xs (reused every train/eval batch).
```

- Build cache: vẫn ~600 encode nhưng **chỉ 1 lần đầu**.
- Train loop: không còn encode CLIP text mỗi batch.

### 3.4. `eval.py`

- Cache tương tự sau `load_checkpoint` khi freeze + `class_desc`.
- `semantic_input(..., phi_cache=)` + `compute_all_scores(..., phi_cache=)`.
- Eval định kỳ **trong Trainer** cũng dùng `_prepare_semantic_input` → hưởng cache.

### 3.5. Không đổi (cố ý)

| Thành phần | Ghi chú |
| --- | --- |
| `HSPRN.forward` API | Vẫn `(text_feature, vision_feature)` |
| `Ws`, IPR, RP bank, matching | Train như cũ |
| Plan 3 policy | Vẫn `class_desc` + itemwise khi **build** cache |
| `data.batch_size` | Vẫn YAML |
| Architecture ResNet/CLIP | Không đổi số layer / loss |

### 3.6. Kỳ vọng tốc độ sau fix (T4, batch 24)

| | Trước | Sau (kỳ vọng) |
| --- | --- | --- |
| CLIP text / batch | ~600 encode | **0** (cache) |
| s/batch | ~6.5 s | Thường **≪ 1 s** (phụ thuộc I/O workers) |
| VRAM | ~1 GB | Có thể **cao hơn** khi vision path thống trị |
